# NeuroGolf · ARC 任务可视化工具

一个**单文件、纯前端、离线可用**的本地工具,用来在浏览器里**一眼看懂每道 ARC 任务的「本质动作」**(input 网格经过什么变换变成 output)。这是后续攻坚选题的基础。

```
Golf2026/
├─ data/                     # 400 个 taskNNN.json(竞赛数据)
├─ task_overview_v32.tsv     # 主表(cost/score/source/LB…)
└─ tools/
   ├─ arc_viewer.html        # ★ 工具本体(单文件)
   ├─ start.py               # 本地服务启动脚本
   ├─ start.bat              # Windows 一键启动
   └─ README.md              # 本文件
```

> 把这 4 个文件放进 `Golf2026/tools/` 即可。工具默认按 `../data` 和 `../task_overview_v32.tsv` 这套相对路径读数据。

---

## 一、怎么启动(两种方式,任选)

### 方式 B(推荐):本地服务,自动读数据
双击 **`start.bat`**(或命令行 `python start.py`)。
脚本会在 `Golf2026` 根目录起一个静态服务,并自动打开浏览器:

```
http://localhost:8011/tools/arc_viewer.html
```

此时 `data/` 和 `task_overview_v32.tsv` 会被**自动读取**,翻题即读即显。
关闭:在弹出的命令行窗口按 `Ctrl+C`。端口被占用会自动顺延;也可 `python start.py 8080` 指定端口。

> 为什么推荐这个:纯 HTML 用 `file://` 直接双击时,浏览器的 CORS 策略会**禁止**它 `fetch` 本地 json/tsv。起个本地 http 服务就绕过了,长期天天用最省事。

### 方式 A:直接双击 html(手动选数据)
如果不想起服务,直接双击 `arc_viewer.html`。它会弹出加载面板:
1. **选择 `Golf2026/data` 整个文件夹**(一次性把 400 个 json 读进内存,之后翻题无需服务);
2. (可选)再选 `task_overview_v32.tsv` 加载主表;
3. 点「用已选数据进入」。

两种方式功能完全一样。

## 二、界面与功能

### 顶栏
- **翻题**:`◀ / ▶` 上一题/下一题;中间输入框填 `1–400` 回车跳转。
- **主表信息条**(右上):当前题的 `source` 徽章(`DEEP`/`PUBLIC`/`BASE`)、`cost`、`score`、`LB` —— 攻坚选题时一眼看到「这题现在多少分、是不是我们攻过的」。
- **Diff 模式**:`聚光 / 描边 / 关`(见下文第三节,这是核心)。
- **网格线 / 缩放 / arc-gen 每页**:按需调,设置会自动记住。

### 主区(纵向三段)
1. **TRAIN**:把每个训练样例的 `input → output` **彩色网格并排**显示,多个样例纵向排列 —— 看「同一个动作」在多个样例上重复,抓住不变的本质。
2. **TEST**:测试样例,用青色边框区分。
3. **ARC-GEN**:约 250 个生成样例,**分页浏览**(不会一次全画)。`◀ ▶` 翻页,或在「跳样例#」填序号直达 —— 看动作在不同尺寸/颜色/参数下怎么变,判断哪些维度是噪声、哪些是结构。

每个网格:
- 用 **ARC 标准配色**渲染(`0=黑 1=蓝 2=红 3=绿 4=黄 5=灰 6=品红 7=橙 8=青 9=褐`),你有肌肉记忆。
- 下方标注尺寸(如 `9×9`);超过 `30×30` 的样例会标 `·>30`(提示:评分时这类被忽略)。
- **鼠标悬停**任意格子,显示 `(行,列) = 数值 颜色名`。

### 侧栏:任务列表(辅助选题)
- 列出全部任务的 `task / cost / score / src`,**点表头可排序**(按编号/成本/得分/来源),例如按 `cost` 降序找「最该压的高成本题」。
- 顶部可**搜索编号**、用 `DEEP/PUBLIC/BASE` 三个标签**筛选来源**。
- 点任意一行跳转到该题;当前题高亮。
- `☰ 列表` 或按 `T` 折叠/展开侧栏。
- (主表没加载时,侧栏退化为 `001–400` 列表,仍可正常翻题。)

### 快捷键
`←/→` 翻题 ｜ `D` 切换 diff 模式 ｜ `G` 网格线开关 ｜ `[ ]` 缩小/放大 ｜ `T` 折叠侧栏

## 三、diff 高亮:怎么「一眼看懂本质动作」

**变化在哪 = 动作是什么。** 工具对每个样例自动比较 input 与 output 的每个格子,标出变化。

**核心设计 —— 输入图是「变换前」的参照,输出图才是「看动作」的地方:**
- **输入图(左)始终保持本色**,不压暗。它是「变换前」的原貌,要看得清清楚楚才好悟规则。唯一例外:当 output 比 input 小(裁剪类)时,**会被裁掉的格子**在输入图上用「压暗 + 白虚线」标出 —— 这样你一眼看到「哪块被保留、哪块被丢弃」。
- **输出图(右)是动作落点**,高亮都画在它上面。

三种模式:
- **聚光(默认)**:在输出图上把**没变的格子压暗**,**变化/新增的格子保持高亮**并描白边。
  → 动作会从背景里「跳」出来,最适合一眼抓住本质。(若该图整张都没变化 —— 例如纯裁剪后输出就是原图的一块 —— 则不压暗,避免整张变黑。)
- **描边**:不压暗,只在变化处画**白色高亮边框**(深色光晕 + 白内环,保证在黄/黑等任何底色上都清晰)。
  - **实线** = 该格颜色变了(changed);
  - **虚线** = 新增格(output 比 input 多出,画在输出图)或被裁格(input 比 output 多出,画在输入图)。
- **关**:只看原始 input/output,不做高亮。

**尺寸不同怎么办**:138/400 的题 input/output 尺寸不同(放大/裁剪类)。工具**左上角对齐**比较:重叠区按上面规则标变化;放大类多出的部分在输出图标「新增」(虚线),裁剪类丢掉的部分在输入图标「被裁」(虚线)。同时箭头下方给出**一句话动作摘要**,例如:
- 同尺寸:`改变 2/36 格`
- 放大类:`3×3 → 9×9 ·放大 ×3`
- 缩小类:`6×6 → 2×2 ·缩小 ×3`

### 三个真实例子(都已实测)

**① `task001` —— 放大/分形(input/output 尺寸不同)**
input 是 `3×3`,output 是 `9×9`,摘要直接写 `·放大 ×3`。
- 左边的 `3×3` 源图案**满色清晰**(比如一组橙色方块、或黄色的对角点),一眼能读懂。
- 右边 `9×9`:**input 里非黑的格子,在 output 对应的 `3×3` 宏块里被替换成「整张 input 的复制」;原本是黑的格子,对应宏块是一片黑** —— 聚光模式把基底压暗、把新铺出来的部分高亮,「平铺」这个动作直接浮出来。
- 本质动作 = **分形自复制(self-tiling)**。看懂这个,就知道该找「能廉价表达『按掩码平铺自身』」的算子(Tile / 外积 / 掩码乘),而不是堆通用卷积。

**② `task002` —— 局部改色(同尺寸,最常见的一类,262/400)**
input/output 都是 `6×6`,摘要 `改变 2/36 格`。
- 左边满屏亮绿(参照),右边聚光模式下**整片绿被压暗,只有 2 个格子变成亮黄、套着白色实线框** —— 一眼看出「规则只把某 2 个特定格子改成黄色」。
- 本质动作 = **按位置/邻域定位 + 改色**。

**③ `task326` —— 裁剪/抽取(output 变小)**
input 是 `6×6`(或 `8×8`),output 是 `2×2`,摘要 `·缩小 ×3`。
- 左边输入图:**左上 `2×2` 满色明亮(被保留),其余格子压暗 + 白虚线(被裁掉)** —— 动作直接显示在输入图上:「取左上角那一小块」。
- 右边输出图:就是那块 `2×2`,**满色明亮**(不压暗)。
- 本质动作 = **裁剪 / 抽取固定区域**,对应思路是切片(Slice / Gather)。

## 四、备注
- 工具的设置(diff 模式、缩放、网格线、上次看的题等)会**自动记住**(localStorage)。
- 主表用**按列名鲁棒解析**:只要表头里有 `task / current_cost / current_score / LB_status / source` 这些列名(大小写不限,`source` 默认取末列),换成 v33+ 的新版主表也能直接用,不必改代码。
- 全程不依赖任何外部网络/CDN,断网也能用。
